# ТЕХНИЧЕСКАЯ ДОКУМЕНТАЦИЯ: СТРУКТУРА БАЗЫ ДАННЫХ ДЛЯ НПА
*(версия с поддержкой версионирования номеров, дублей, структурированных таблиц, массивов примечаний и источника примечания)*

---

## Общие принципы

База данных предназначена для полного жизненного цикла нормативно-правовых актов (НПА):

- импорт из JSON‑структуры,
- иерархическое хранение элементов (статьи, пункты, разделы, приложения, структурированные таблицы),
- версионирование каждого элемента (редакции контента, заголовков, номеров, служебной информации),
- отслеживание изменений с подсветкой (diff),
- поддержка сложных связей между документами, авторами, должностями, комитетами,
- хранение примечаний с возможностью явно связать их с НПА, который вызвал появление примечания.

**Ключевые особенности:**

- Каждый структурный элемент имеет уникальный строковый `item_id`, который неизменен в течение всего срока жизни элемента – это обеспечивает стабильность всех ссылок (например, `child_ref`, `modified_by_id`, `not_valid`).
- При дублировании номеров (ошибки законодателя) в `item_id` добавляется суффикс `_double_N` (N=1,2,…), что позволяет различать элементы с одинаковыми номерами.
- Номера элементов могут меняться со временем – для этого ведётся отдельная таблица истории номеров (`npa_item_number_revision`), при этом `item_id` остаётся прежним.
- Редакции контента, заголовков и префиксов хранятся с указанием периодов действия (`valid_from` / `valid_to`) и идентификаторами документов, инициировавших изменение.
- Для визуализации различий между редакциями используется JSON‑поле `highlights` в соответствующих таблицах.
- Добавлено поле `not_valid_npa_id` в таблицу `npa_base` для прямой ссылки на НПА-отменитель (числовой идентификатор), что дополняет строковое поле `not_valid_note`.
- Для примечаний в `npa_note_unified` может быть указан `source_item_id` — внутренний ID элемента `npa_item`, принадлежащего НПА, который вызвал появление примечания. Поле допускает `NULL`, поскольку источник изменения может отсутствовать в БД или не быть представленным как НПА.

## 4. Структурированные таблицы (`structured_table`)

Элемент типа `structured_table` не отображается в оглавлении и не имеет собственного якоря. Его дочерние элементы (только типы `section`, `point`, `subpoint`) присутствуют в `npa_item` и участвуют в оглавлении.

Содержимое такой таблицы хранится следующим образом:

- Для самого `structured_table` в его редакциях могут быть блоки:
  - `table_header` – шапка таблицы (HTML `<thead>`).
  - `paragraph` – пояснительный текст.
  - `child_ref` – ссылки на дочерние элементы (пункты, подпункты).
- Для каждого дочернего элемента (`section`, `point`, `subpoint`) в его редакциях присутствуют блоки `table_fragment`, содержащие одну или несколько строк (`<tr>`) таблицы, относящихся к этому элементу.
- При версионировании изменения в строках таблицы создают новые редакции соответствующего пункта/подпункта.

**Правила распознавания структурных строк:**

- Строка с единственной ячейкой, начинающейся со слова «Раздел», считается разделом (`section`).
- Строка, первая ячейка которой начинается с нумератора (цифра с точкой, римская цифра, буква со скобкой и т.п.), считается пунктом (`point`) или подпунктом (`subpoint`) в зависимости от количества разделителей и вложенности.
- Остальные строки обрабатываются как неструктурированный текст и помещаются в `table_fragment` без создания отдельного элемента.

## 6. Справочная информация (примечания) – таблица `npa_note_unified`

В JSON-структуре для НПА и отдельных элементов могут быть массивы примечаний (`npa_notes` и `item_notes`). Каждый элемент массива содержит:

- `text` – текст примечания;
- `valid_from` – дата начала действия примечания;
- `valid_to` – дата окончания действия примечания (необязательно).

В базе данных эти сведения хранятся в единой таблице.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INT UNSIGNED | Первичный ключ |
| `npa_id` | INT UNSIGNED | Ссылка на `npa_base` |
| `source_item_id` | INT UNSIGNED NULL | Источник примечания: `npa_item.id` элемента изменяющего НПА. `NULL` — источник не представлен в БД или не является НПА из БД |
| `target_type` | ENUM('npa','toc','item') | Тип объекта: `'npa'` – ко всему документу, `'item'` – к конкретному элементу |
| `target_id` | VARCHAR(150) | Для `'item'` – строковый `item_id` элемента; для `'npa'` – NULL |
| `note_text` | TEXT | Текст примечания |
| `valid_from` | DATE | Дата начала действия примечания для примечаний без `source_item_id`; для примечаний с `source_item_id` сохраняется исходная дата примечания и она не определяет принадлежность к редакции |
| `valid_to` | DATE | Дата окончания действия примечания. Если задана, является безусловной верхней границей отображения примечания |

### 6.1. Семантика `source_item_id`

Поле `source_item_id` вводится для явного отделения **источника примечания** от **дат его юридического действия**.

Если `source_item_id IS NOT NULL`:

1. `source_item_id` указывает на `npa_item.id`, принадлежащий НПА, который вызвал появление примечания.
2. Примечание относится к редакции, вызванной этим НПА, и ко всем последующим (более новым) редакциям этого НПА.
3. `valid_from` **не используется для определения принадлежности примечания к редакции**. Это позволяет корректно обрабатывать ретроактивное действие и ситуации, когда дата действия примечания раньше даты принятия изменяющего НПА.
4. `valid_to`, если задана, является безусловной верхней границей: после этой даты примечание не отображается ни в одной редакции.
5. Если выбранная редакция старше редакции, вызванной `source_item_id`, примечание не отображается.

Если `source_item_id IS NULL`:

1. Используется прежняя логика, не привязанная к конкретному НПА-источнику.
2. Примечание отображается только при выполнении:
   - `valid_from <= дата просмотра` (или `valid_from IS NULL`, если это допускается текущей схемой);
   - `valid_to IS NULL OR valid_to >= дата просмотра`.
3. Такое примечание не получает автоматически привязку к редакции и не переносится на неё только из-за даты принятия какого-либо НПА.

### 6.2. Примеры

**Пример 1. Изменение внесено НПА №569-ЗС, но распространяется на правоотношения с 01.01.2020:**

```text
source_item_id = элемент НПА №569-ЗС
valid_from     = 2020-01-01
valid_to       = NULL
```

При просмотре редакции №569-ЗС и всех последующих редакций примечание отображается. При просмотре редакции, предшествующей №569-ЗС, — нет.

**Пример 2. НПА №571-ЗС принят позже, но его действие распространяется на более ранние правоотношения:**

```text
source_item_id = элемент НПА №571-ЗС
valid_from     = 2020-01-01
valid_to       = NULL
```

При просмотре редакции №569-ЗС примечание **не отображается**, потому что источник примечания относится к более новой редакции. При просмотре №571-ЗС и последующих редакций — отображается.

**Пример 3. Источник не представлен в БД:**

```text
source_item_id = NULL
valid_from     = 2020-01-01
valid_to       = NULL
```

Применяется только датовая логика `valid_from` / `valid_to`.

### 6.3. Импорт

- Записи из `npa_notes` и `item_notes`, для которых известен НПА-источник и этот источник представлен в `npa_item`, записываются с соответствующим `source_item_id`.
- Если источник отсутствует в БД, не является НПА из БД либо однозначно не может быть сопоставлен с `npa_item`, `source_item_id` устанавливается в `NULL`.
- `valid_from` и `valid_to` сохраняются из исходных данных.
- Отсутствие `source_item_id` не является ошибкой: оно означает использование датовой модели отображения.

## 10. Принципы версионирования и ссылочной целостности

- Все таблицы ревизий (заголовков, контента, префиксов, номеров) имеют поля `valid_from`, `valid_to`, `not_valid`, `modified_by_id`, что позволяет точно восстановить состояние документа на любой момент времени.
- `npa_note_unified.source_item_id`, если заполнен, хранит числовой `npa_item.id` элемента-источника.
- `source_item_id IS NULL` является допустимым состоянием и означает, что источник изменения не представлен в БД либо не является НПА из БД.
- При удалении НПА источник примечания должен обнуляться (`ON DELETE SET NULL`), а само примечание не должно удаляться автоматически.
- `modified_by_id` и `not_valid` хранят строковые `item_id` (или числовые id) – при импорте они преобразуются в числовые идентификаторы или остаются в виде строк для совместимости.
- При удалении НПА все связанные записи удаляются каскадно (благодаря внешним ключам `ON DELETE CASCADE`), за исключением `npa_note_unified.source_item_id`, для которого используется `ON DELETE SET NULL`.

## 11. Обработка дублирующихся номеров

При дублировании номера в одном НПА (например, две статьи с номером «5») второму элементу присваивается `item_id` с суффиксом `_double_1` (и далее по возрастанию). При последующем исправлении номера (например, на «5.1») `item_id` остаётся неизменным, а новое значение номера фиксируется в таблице `npa_item_number_revision`. Это гарантирует, что все ссылки (из `child_ref`, `modified_by_id`, `not_valid` и т.п.) остаются корректными.
